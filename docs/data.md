# Слой данных

Динамическое хранилище с мета-схемой.

← [Edem](./edem.md)

## Коллекции

Именованные наборы данных (аналог таблиц). Каждая коллекция определяется набором полей.

## Поля

Описания типов данных внутри коллекций. Поддерживаются типы: строки, числа, булевы, даты, JSON, файлы, изображения, видео, связи, UUID, timestamp и другие.

## Items

Единицы данных внутри коллекций. Все значения хранятся как единая структура.

## Связи

Ссылки между items разных коллекций (M2M и O2M). Поддерживают сортировку.

## Файлы

Content-addressable хранилище. Каждый файл идентифицируется хэшем содержимого. Автоматическая дедупликация. Поддерживаются миниатюры, метаданные медиа (размеры, длительность, кодеки).

## Системные возможности

- **Версионирование** — автоматические снапшоты перед каждым обновлением
- **Блокировки** — оптимистичная блокировка с TTL для параллельного редактирования
- **Soft deletes** — мягкое удаление с возможностью восстановления
- **Миграции** — ленивые изменения схемы (не перезаписывают данные мгновенно)
- **i18n** — строковые значения могут быть многоязычными

## Два режима

- **Development** — динамическая схема, полный CRUD на мета-уровне (создание/изменение коллекций и полей)
- **Runtime** — фиксированная схема, только операции с данными

## Dynamic Schema

Схема коллекций и полей хранится отдельно от самих данных. Коллекции и поля описываются как метаданные, а единицы данных (items) — единая структура с произвольным набором значений. Это позволяет изменять структуру приложения (добавлять/удалять поля) без миграции хранилища и без потери существующих данных. Версия схемы хранится на уровне коллекции и на уровне каждого элемента для совместимости.

## Content-Addressed Storage

Файлы идентифицируются хэшем содержимого, а не именем или идентификатором. Одинаковое содержимое всегда даёт один и тот же хэш, что обеспечивает автоматическую дедупликацию: при загрузке дубликата создаётся ссылка на существующий файл. Файлы распределяются по каталогам по двум первым символам хэша для избежания проблем с производительностью файловой системы при большом количестве файлов. Каждый файл имеет счётчик ссылок для отслеживания использования и очистки осиротевших записей.

## In-Memory Query Engine

Фильтрация, сортировка и поиск выполняются над загруженными данными в памяти, а не на уровне базы данных. Это обусловлено тем, что данные хранятся как JSON-структуры, к которым не применимы SQL-индексы. Движок поддерживает операторы сравнения (равно, не равно, больше, меньше, содержит, начинается/заканчивается на, вхождение в диапазон/множество), логические комбинаторы (и, или) и полнотекстовый поиск по всем строковым значениям элемента. Сортировка и фильтрация учитывают локализацию: при наличии локали разрешение значения происходит до сравнения.

## Lazy Migration

Изменения структуры данных (добавление, удаление, переименование полей, изменение типов) не применяются мгновенно ко всем элементам. Операции миграции записываются в журнал и выполняются пакетно при обращении к конкретным элементам. Это исключает простои при работе с большими объёмами данных и позволяет отложить трансформацию до момента, когда элемент фактически используется.

## Optimistic Locking

Для параллельного редактирования элементов используется оптимистичная блокировка с временным ограничением (TTL). При блокировке указывается владелец и время жизни. Если блокировка истекла, она автоматически очищается при следующей проверке и может быть перехвачена другим процессом. Принудительное снятие блокировки доступно без проверки владельца.

## Soft Deletes

Удаление элементов и коллекций — мягкое: устанавливается временная метка удаления, но запись сохраняется. Это позволяет восстанавливать удалённые данные. Окончательное удаление (очистка корзины) выполняется явным запросом. Все запросы автоматически фильтруют удалённые записи.

## Singleton Collections

Коллекции с пометкой «singleton» ограничены одним элементом. Используются для хранения настроек, конфигураций и глобального состояния приложения. При первом обращении элемент создаётся автоматически с значениями по умолчанию из схемы.

## Manifest-Driven Schema Sync

Декларативная идемпотентная синхронизация состояния базы данных с описанием в манифесте. За один проход создаются отсутствующие коллекции и поля, обновляются изменённые (тип, обязательность, метаданные, значения по умолчанию), удаляются лишние. Результат разбивается на категории: созданные, обновлённые, пропущенные — для отслеживания изменений. При добавлении новых полей в singleton-коллекции значения по умолчанию автоматически заполняются в существующий элемент.

## Localization

Строковые значения хранятся как многоязычные объекты (ключ — код локали, значение — перевод). При чтении данных с указанием локали происходит автоматическое разрешение: приоритет — запрошенная локаль, затем локаль по умолчанию, затем первое доступное значение. Локализация учитывается при фильтрации, сортировке и полнотекстовом поиске.
