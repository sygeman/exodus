# Слой логики

DAG-движок для бизнес-логики. Потоки описывают последовательность операций как граф нод, соединённых рёбрами.

← [Edem](./edem.md) · Реализация: [edem-flows](../packages/edem-flows/README.md)

## Ноды

Единицы вычислений. Типы нод по назначению:

- **Логика** — условия, ветвление, итерации, задержки
- **Данные** — входы и выходы потока
- **Трансформации** — операции над данными (set, add, multiply, append)
- **Внешние** — вызовы зарегистрированных хендлеров, вложенные потоки
- **Поток** — параллельные ветки и их агрегация

## Триггеры

Что инициирует выполнение:

- **Event** — реакция на системные события (создание, обновление, удаление данных)
- **Schedule** — выполнение по расписанию (интервал, время, дни недели)
- **Manual** — ручной запуск пользователем
- **Webhook** — HTTP callback

## State machine выполнения

```
pending → running → waiting → completed
                       ↓
                     error | cancelled
```

## Шаблонные выражения

`{{ scope.path }}` для доступа к данным в контексте выполнения: входные данные триггера, выходы предыдущих нод, переменные потока.

## Особенности

- **Асинхронные ноды** — некоторые ноды могут приостановить выполнение и возобновить позже
- **Retries** — экспоненциальный backoff с настраиваемым количеством попыток
- **Timeouts** — ограничение времени на ноду
- **Backpressure** — лимиты на параллельные и ожидающие запуски
- **Валидация** — проверка графа на циклы, корректность ссылок, наличие триггера

## Fork/Join

Разветвление графа на несколько веток с последующим слиянием. При достижении ноды fork граф разделяется на ветки, каждая из которых выполняется независимо. При слиянии (join) агрегируются результаты всех веток. Поддерживаются три режима агрегации: все ветки, любая ветка, N из M веток. Если какая-либо ветка содержит асинхронную ноду, выполнение приостанавливается до возобновления.

## Async Nodes

Нода может приостановить выполнение потока и возобновить его позже через внешний вызов. Это позволяет интегрировать длительные операции (ожидание ответа от пользователя, HTTP-запрос, таймер) без блокировки всего графа. Состояние выполнения (включая промежуточные данные) сохраняется и восстанавливается при возобновлении.

## Adaptive Execution

При выполнении ноды action движок проверяет наличие зарегистрированного обработчика. Если обработчик есть — нода выполняется синхронно и передаёт управление следующей ноде. Если обработчика нет — нода переходит в состояние ожидания (async), и выполнение возобновляется только после внешнего вызова с предоставлением результата. Это позволяет одному и тому же потоку работать в разных режимах в зависимости от доступных обработчиков.

## Subflows

Вложенные потоки выполняются синхронно в контексте родительского. Если дочерний поток содержит асинхронные ноды, его состояние ожидания пропагируется в родительский поток. Результат выполнения дочернего потока доступен в родительском через шаблонные выражения.

## Template Expressions

Система разрешения выражений вида `scope.path` для доступа к данным в контексте выполнения. Три области видимости: данные триггера (входные параметры запуска), выходы нод (результаты выполнения предыдущих шагов), переменные потока (изменяемое состояние: счётчики циклов, результаты слияний). Выражения разрешаются в свойствах компонентов, тексте, условиях и конфигурациях нод.

## Backpressure

Управление нагрузкой через лимиты на количество параллельных и ожидающих запусков одного потока. Последовательная обработка запросов через мьютекс предотвращает гонки, когда несколько одновременных запусков одновременно проверяют лимиты и превышают их. При превышении лимита запуски ставятся в очередь.

## Retries

При ошибке выполнения ноды автоматическое повторение с экспоненциальной задержкой. Каждая попытка увеличивает задержку (базовая × 2^(попытка-1)). Количество повторов и базовая задержка настраиваются индивидуально для каждой ноды.

## Timeouts

Ограничение времени выполнения ноды. Если нода не завершилась за отведённое время, выполнение принудительно завершается с ошибкой. Для асинхронных нод таймаут проверяется периодически через планировщик.

## State Machine

Полный жизненный цикл выполнения: pending (ожидание запуска) → running (выполняется) → waiting (приостановлено, ожидает внешнего вызова) → completed (успешно завершено) | error (ошибка) | cancelled (отменено). Terminal-состояния (completed, error, cancelled) не имеют переходов. Валидация переходов предотвращает некорректные смены состояний.

## Dispatcher

Маршрутизация событий на основе шаблонов имен. Системные события (создание, обновление, удаление элементов) автоматически запускают привязанные потоки с фильтрацией по коллекции. Webhook-триггеры реагируют на HTTP-запросы по уникальным путям. При старте dispatcher строит индекс потоков по событиям и путям для быстрой маршрутизации.

## Scheduler

Выполнение потоков по интервалам или расписанию. Интервалы задаются в минутах, часах или днях. Планировщик проверяет delayed runs и таймауты асинхронных нод с фиксированной частотой. При изменении набора потоков таймеры динамически обновляются.
