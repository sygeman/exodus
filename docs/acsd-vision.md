# ACSD + Edem: Общая архитектура

## Суть

Человек описывает намерение. Система генерирует работающее приложение.
Каждый элемент кода связан с намерением. Валидатор не позволяет нарушить цепочку.

## Уровни детально

### L0 — Intent

**Что это:** Структурированное описание того, ЧЕГО хочет человек.

**Формат:** JSON (не markdown)

```json
{
  "id": "intent-01",
  "description": "Приложение для заметок с тегами и офлайн-режимом",
  "goals": [
    { "id": "G-01", "text": "Создавать, редактировать, удалять заметки" },
    { "id": "G-02", "text": "Назначать теги заметкам" },
    { "id": "G-03", "text": "Работать без интернета" }
  ],
  "constraints": [
    { "id": "C-01", "text": "Мобильный приоритет" },
    { "id": "C-02", "text": "Без серверной части, всё локально" }
  ],
  "non_goals": [
    { "id": "NG-01", "text": "Нет синхронизации между устройствами" }
  ],
  "examples": [
    "Apple Notes, но проще",
    "Google Keep с тегами"
  ]
}
```

**Кто генерирует:** Агент (из разговора с человеком) или человек вручную.

**Валидация:** LLM-проверка — нет ли противоречий между goals и constraints.

---

### L1 — Architecture

**Что это:** Какие слои Edem нужны и какие решения приняты.

**Формат:** JSON

```json
{
  "id": "arch-01",
  "covers": ["G-01", "G-02", "G-03"],
  "layers": {
    "data": {
      "collections": ["notes", "tags", "note_tags"],
      "rationale": "G-01 → notes, G-02 → tags + junction table"
    },
    "flows": {
      "patterns": ["CRUD", "filter_by_tag"],
      "rationale": "G-01 → CRUD flows, G-02 → filter flow"
    },
    "ui": {
      "screens": ["notes_list", "note_editor", "tag_manager"],
      "rationale": "G-01 → list + editor, G-02 → tag manager"
    },
    "platform": {
      "target": "electrobun",
      "rationale": "C-01 → desktop app"
    }
  },
  "decisions": [
    {
      "id": "D-01",
      "question": "Как хранить связь many-to-many?",
      "answer": "Junction table note_tags",
      "covers": "G-02"
    }
  ]
}
```

**Кто генерирует:** Оркестратор (ACSD engine) из L0.

**Валидация:**
- Все G-* из L0 покрыты хотя бы одним слоем
- Нет слоёв без обоснования в L0
- D-* не противоречат constraints

---

### L2-L3 — Edem Manifests

**Что это:** Текущие Edem-манифесты. Структурированное описание приложения.

**Уже реализовано:**
- `data.json` — коллекции и поля
- `flows.json` — потоки и ноды
- `components/*.json` — дерево UI-компонентов
- `routes.json` — маршруты
- `platform.json` — bridge, persistence

**Валидация (уже есть):**
- `validateIR` — перекрёстные ссылки между слоями
- `validateFlow` — граф корректен (acyclicity, connectivity)

**Что нужно добавить:**
- Ссылки на L1: каждый манифест указывает `covers: ["D-01", ...]`
- Валидация L1→L2: все решения из L1 реализованы в манифестах

---

### L4 — Tests

**Что это:** Контрактные тесты, генерируемые из манифестов.

**Что уже есть (частично):**
- `validateFlow` проверяет граф
- `validateIR` проверяет ссылки
- Тесты в `packages/edem-flows/` проверяют executors

**Что нужно:**
- Автогенерация тестов из data-схем (CRUD-операции существуют)
- Автогенерация тестов из flow-контрактов (ноды вызываются, результаты корректны)
- Автогенерация тестов из UI-контрактов (компоненты рендерятся, события работают)

**Формат:** Стандартные тесты (vitest/bun:test), не отдельный формат.

---

### L5 — Code

**Что это:** Сгенерированный код.

**Уже реализовано:**
- `edem-codegen` — pipeline: манифесты → IR → stages → файлы
- Стages: bun, electrobun, vue, data, flows, app, platform

**Что нужно добавить:**
- Метаданные в сгенерированном коде: `// covers: G-01, D-01, manifest:data.json`
- Traceability: каждый файл/функция связана с манифестом и intent

## Валидация

### Три типа

| Тип | Что проверяет | Как |
|-----|--------------|-----|
| **Механическая** | Целостность ссылок, формат, типы | Движок (без LLM) |
| **Кросс-уровневая** | Соответствие между уровнями | LLM + правила |
| **Сквозная** | Код соответствует намерению | LLM (цепочка L5→L0) |

### Механическая (уже есть)

```
validateIR(manifests) → ValidationError[]
validateFlow(flow)    → { valid, errors }
```

### Кросс-уровневая (нужно построить)

```
validateLevel(L0, L1) → "Все goals покрыты?"
validateLevel(L1, L2) → "Все решения реализованы?"
validateLevel(L2, L5) → "Код соответствует манифестам?"
validateLevel(L5, L4) → "Тесты проходят?"
```

### Сквозная (нужно построить)

```
validateChain(L0, L5) → "Весь код обоснован намерением?"
```

Это LLM-проверка: дать модели весь контекст от intent до кода и спросить:
1. Есть ли элементы кода без обоснования в L0?
2. Есть ли элементы L0, не реализованные в коде?
3. Есть ли противоречия в цепочке?

## Оркестратор (ACSD Engine)

### Что делает

1. **Генерация L0→L1:** Из intent генерирует architecture
2. **Генерация L1→L2:** Из architecture генерирует Edem-манифесты
3. **Генерация L2→L5:** Запускает codegen
4. **Генерация L5→L4:** Генерирует тесты
5. **Валидация:** На каждом переходе проверяет цепочку
6. **Анализ влияния:** При изменении L0 считает затронутые узлы

### Как работает

```
1. Человек: «Добавить сортировку по дате»
2. Оркестратор:
   a) Обновляет L0 (добавляет цель G-04)
   b) Анализ влияния: G-04 → нужно обновить flows (сортировка)
     и UI (порядок списка)
   c) Показывает человеку: «Затронуты: flows.json, components/notes_list.json. Вот что изменится:»
   d) Человек подтверждает
   e) Обновляет манифесты
   f) Запускает codegen
   g) Валидирует цепочку L5→L0
   h) Фиксирует изменения
```

### Инварианты

- **Идемпотентность:** Повторный запуск даёт тот же результат
- **Атомарность:** Либо весь каскад проходит, либо ничего не применяется
- **Нет скрытых изменений:** Человек видит каждый шаг до применения
- **Traceability:** Любой элемент можно追溯до L0

## Интерфейс

### Человек → Система

- **Чат с агентом** (основной) — «Хочу приложение для заметок»
- **Команды** (опционально) — `acsd check`, `acsd trace G-01`
- **GUI** (Exodus) — визуальное представление манифестов

### Система → Человек

- **Предложение манифестов** — «Я сгенерировал data-схему. Вот что получилось:»
- **Диффы** — «При добавлении сортировки изменятся эти файлы:»
- **Валидация** — «Цепочка нарушена: G-03 не реализован в flows.json»
- **Трассировка** — «Этот код соответствует G-01 через D-01 → data.json → composables/...»
