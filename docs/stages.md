# Edem — Стадии развития

## Философия

Приложение = набор манифестов. Разработчик **объявляет**, никогда не пишет код.

```
Манифесты → Codegen → Готовое приложение
```

Манифесты:
- `data.json` — какие данные существуют
- `flows.json` — что происходит когда
- `routes.json` — маршруты и компоненты (UI)
- `platform.json` — платформенные фичи
- `assets.json` — статические ресурсы

## Стадии

### Стадия 1: Gold Standard

Создаём **идеальный пример** приложения — написан вручную, чистый, правильный.

Это `apps/exodus`. Сейчас в нём есть hand-written код, который **должен** генерироваться из манифестов.

Цель стадии: определить **как выглядит идеальное приложение Edem** и **что именно codegen должен генерировать**.

### Стадия 2: Codegen

Переписываем codegen чтобы он **полностью** генерировал gold standard из манифестов.

Граница ответственности:
- Codegen генерирует **всё**: boilerplate, platform, composables, компоненты, конфиги
- Манифесты — **единственный** источник правды
- Никакого hand-written кода в готовом приложении

### Стадия 3: Работа с манифестами

Всё развитие приложений = работа с JSON-манифестами.

- Создаём новые приложения через манифесты
- Редактируем фичи через манифесты
- Codegen генерирует готовый код

### Стадия 4: Exodus IDE

GUI для работы с манифестами — визуальное программирование.

- Редактор данных (data.json)
- Редактор потоков (flows.json)
- Редактор UI (routes.json + компоненты)
- Управление проектами
- Build-пайплайн

### Стадия 5: Self-Development

Exodus развивается в самом себе.

```
build(exodus) = exodus
```

Exodus IDE позволяет редактировать манифесты exodus → codegen генерирует новый exodus.

## Gap-и codegen (Стадия 2)

Текущий codegen **не генерирует**:

| Что | Описание | Откуда берётся |
|-----|----------|----------------|
| Webview-side logger | Логгер в webview с dedup, query, stats, clear | `platform.json` → `consoleLogger` |
| i18n в main.ts | vue-i18n инициализация | Компоненты с переводами |
| useAppState | Восстановление locale/theme/route из app_state | `platform.json` → `systemDetection` |
| useT | Composable для переводов | Компоненты с переводами |
| useUpdaterStatus | Singleton для статуса апдейтера | `platform.json` → `updater` |
| Rich composables | Пагинация, фильтрация, навигация | Метаданные коллекций в `data.json` |

### Rich composables — ключевой gap

Сейчас codegen генерирует простые CRUD-composables. Нужно генерировать rich-версии на основе метаданных коллекций:

```json
{
  "id": "logs",
  "fields": [...],
  "composable": {
    "pagination": true,
    "pageSize": 100,
    "filterBy": ["level", "source"],
    "search": "message",
    "stats": true
  }
}
```

Так codegen будет знать какие фичи нужны composable-у.
